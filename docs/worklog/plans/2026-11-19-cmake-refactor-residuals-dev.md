# Задание разработчику: остатки по обзору + прогон 1 сервер / 10 клиентов (1–2 мин)

Адресат: developer
Дата: 2026-11-19
Ветка: `cmake-refactor`, репозиторий `D:\Projects\Client-Server-exchange`

## Цель

Закрыть два остатка из отчёта тестера (остаточные риски A4/A3) и провести короткий
нагрузочный прогон из ТЗ (1 сервер + 10 клиентов), уложив его в 1–2 минуты вместо 10–20.

## Что сделать

### 1. Убрать `numbers.dmp.tmp` после неудачной замены (остаток A3)

`Core/src/dump_writer.cpp`: если `rename(tmp_, file_)` не удался (и fallback не помог) —
best-effort удалить `tmp_` (ошибку удаления игнорировать), залогировать как сейчас. Прежний
`numbers.dmp` остаётся нетронутым. После неудачной попытки в каталоге не должно оставаться
`*.tmp`.

### 2. Тест на бросающий `snapshot_fn_` (остаток A4)

`Tests/dump_writer_test.cpp`: новый тест, где `snapshot_fn_` бросает `std::runtime_error` на
первом вызове, а на втором возвращает `{1, 2}`. Требования:
- поток дампера не завершает процесс (`std::terminate`/падения нет);
- ошибка попадает в логгер (тестовая реализация `ILogger` фиксирует вызов `error`);
- после следующего тика файл дампа записан и содержит `1, 2` (`uint32` подряд);
- тест не зависит от «спать ровно N мс»: используйте короткий интервал (50–100 мс) и ожидание
  условия с дедлайном.

### 3. Прогон 1 сервер + 10 клиентов, 1–2 минуты (вместо 10–20 из ТЗ)

Из `build/Release` (сначала `cmake --build build --config Release`):
- сервер: `cse_server.exe --dump-interval 5` в отдельном каталоге;
- 10 копий/экземпляров `cse_client.exe` одновременно (можно из одного каталога, но у каждого
  свой `client.log` — запускайте из разных каталогов, чтобы логи не конфликтовали);
- длительность ~90 с, затем штатная остановка: серверу — ESC (или `stop`-путь, если в среде
  нет интерактивной консоли — тогда зафиксируйте, чем именно остановли; автотесты
  `IntegrationServer.StopWithConnectedClientIsFast` покрывают graceful-stop);
- после остановки: процессов `cse_*` не осталось, зомби нет.

В отчёт по прогону: количество чисел в `numbers.dmp` (и что оно равно `4 × N`),
фактическое среднее, объём `server.log`/`client.log`, пиковый объём памяти сервера
(например, `Get-Process cse_server | Select WorkingSet`), были ли ошибки в логах,
завершились ли процессы.

## Чего НЕ делать

- Не коммитить (коммит делает ведущий).
- Не менять протокол, формат/имя дампа, имена логов, `docs/**`, `spdlog-1.x/**`.
- Не удалять файлы и каталоги.
- Не расширять скоуп: только пункты 1–3.
