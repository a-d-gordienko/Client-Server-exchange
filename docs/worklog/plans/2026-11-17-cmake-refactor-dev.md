## Цель

Реализовать весь план архитектора: перевести проект на CMake, переписать по SOLID/DRY/KISS
с GoF-паттернами и покрыть GoogleTest — поведение по ТЗ сохраняется, кроме трёх сознательных
изменений (глобальное хранилище, бинарный `numbers.dmp`, удаление синглтонов).

## Входные данные (читать оба файла полностью)

1. **Арх-план:** `docs/worklog/plans/2026-11-17-cmake-refactor-arch.md` — задачи 1–14,
   карта файлов, диаграммы, `Interfaces:`-блоки с точными сигнатурами, таблица T1–T12.
2. **Дизайн:** `docs/superpowers/specs/2026-11-17-cmake-refactor-design.md` — ТЗ, структура,
   таблица паттернов, план проверки.

План обязателен к исполнению: имена, сигнатуры, пути и значения из `Interfaces:` и шагов
задач не придумывай заново. Если план где-то противоречит сам себе — следуй design doc и
отметь расхождение в отчёте.

## Что сделать

- Задачи 1–13 из плана — полностью (CMake-каркас, `Core/include/cse/*`, `Server/main.cpp`,
  `Client/main.cpp`, `Tests/*`, `cmake/*`).
- Задача 14 — только код (`main`-ы, сквозная сборка); ручной прогон «1 сервер + 10 клиентов
  10–20 минут» не запускай, он делается отдельно по команде пользователя.
- Сборка и тесты обязательны:
  ```
  cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DBOOST_ROOT=D:/libs/boost_1_92_0
  cmake --build build --config Release
  ctest --test-dir build -C Release --output-on-failure
  ```
  Все тесты T1–T12 (кроме ручного сквозного) должны проходить.
- Все 12 пунктов плана проверки из design doc §7 покрыть тестами ровно в тех задачах, где
  они указаны в таблице плана.

## Чего НЕ делать

- **Не коммитить.** Шаги «Commit» из плана пропусти: оставь всё в рабочем дереве, коммит
  делает ведущий по команде пользователя.
- **Не удалять и не переписывать старые файлы**: `ClientServerExchange.sln`,
  `Server/*.vcxproj*`, `Client/*.vcxproj*`, `Server/connect.h`, `Server/srv.h`,
  `Server/SrvAlg.h`, `Server/dumper.h`, `Client/client.h`, `Client/clnAlg.h`,
  `spdlog-1.x/**`. Новый код живёт рядом, старый MSBuild-мир не поддерживается.
  Никаких `git clean`, `git restore`, `git checkout --`.
- Не менять протокол: запрос `uint32` (4 байта), ответ `uint64` (8 байт), host order, порт
  64000 по умолчанию.
- Не добавлять зависимости сверх Boost 1.92, vendored spdlog (`spdlog-1.x`), GoogleTest
  (FetchContent 1.15.2, с fallback на системный).
- Не делать кроссплатформенность: Windows-only, `conio.h` за интерфейсом.
- Не трогать `_build/`, `x64/`, каталоги `1..10` — это артефакты предыдущей сборки.

## Критерии готовности

- `cmake` конфигурируется и собирает `cse_core`, `cse_server`, `cse_client`, `cse_tests`
  без ошибок; предупреждения MSVC /W4 — только неустранимые, перечислены в отчёте.
- `ctest` показывает PASS для всех тестов, соответствующих T1–T12 из плана проверки
  (`docs/worklog/plans/2026-11-17-cmake-refactor-arch.md`, §4, таблица T1–T12 → задача → команда).
- Синглтонов и макросов `SERVER`/`CLIENT`/`log_write` в новом коде нет; `parallel_queue`
  в новом коде отсутствует.
- Дамп пишется бинарно, `uint32` на число, файл `numbers.dmp`, отдельный поток, перезапись
  через `tmp` + `rename`.
- Среднее считается глобально по всем уникальным числам, включая только что полученное.
